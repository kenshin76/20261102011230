  1. 01

    하나의 가격 계산 기준

    옵션 조합별 기준가에 회원 유형별 할인(대학 약 5%, 관리자 설정)과 상품별 예외(할인 제외·고정가)를 적용합니다. 상품 상세·장바구니·새 견적·직접 주문에 서버의 공통 가격 계산 로직을 적용하며, 비회원·승인 대기·반려 회원의 가격 조회는 차단합니다.

  2. 02

    발행 견적의 금액 보존

    중복 없는 견적번호를 발급하고 품목·수량·단가·할인·배송비·세액·유효기간·공급자 정보·직인을 발행 시점의 값으로 저장해 PDF로 제공합니다. 이후 가격이 바뀌어도 유효한 견적은 원래 금액을 유지해 주문으로 전환합니다. 중복 전환은 막고 주문에 원 견적번호를 남깁니다.

  3. 03

    결제·증빙과 후속 처리 연결

    PG 결제는 시도별 식별자를 부여하고 서버에서 금액·승인 결과를 검증합니다. 무통장 입금은 기한을 안내하고 관리자가 입금을 확인합니다. 세금계산서는 발행 대상 주문별 고유 관리번호를 사용하고, 외부 응답이 끊기면 기존 결과부터 조회해 중복 처리를 막습니다. 전체 취소·전액 환불과 원 문서에 연결한 수정 발행을 지원하며 처리 이력을 남깁니다.

필수 ② 성공적인 마무리의 기준과 결과물에 대한 의견

핵심은 「견적서를 믿고 바로 주문할 수 있는가」이며 다음 기준으로 확인하겠습니다.

  1. 1즉시 견적 발행 — 견적 생성 API p95 1초·PDF 응답 시작 p95 2초 이내를 확인하고, 견적번호 50건 동시 발행 시 중복 0건을 검증합니다.
  2. 2금액 오차 0원 — 같은 조건의 상세·장바구니·새 견적 계산을 대조하고, 발행 견적 → 주문 → 결제·증빙 금액이 보존되는지 확인합니다.
  3. 3실거래·직접 운영 완료 — 귀사 승인 아래 소액 PG 실결제·취소, 무통장 입금 확인, 발행 대상 주문의 세금계산서 발행을 각각 1건 이상 완료합니다. 담당자의 직접 운영(엑셀 가격 등록·가입 승인·입금 확인·발행), 모바일 360~430px 전 과정, 소스·문서를 이용한 재배포도 검증합니다.

성능 시험에는 제안서 §9-1의 데이터·서버·시험 조건을 적용합니다. 상품 1,200개·옵션 가격 행 3,600개·견적 20,000건·장바구니 30품목, 앱 4 vCPU/8 GiB·DB 2 vCPU/4 GiB 이상에서 같은 리전의 동시 사용자 10명·API와 PDF 요청 각각 300회 이상으로 p95(요청의 95%가 이 시간 안에 응답)를 측정합니다.

PDF는 요청부터 응답이 시작될 때까지의 시간을 측정하며, 외부 API·사용자 통신망 지연은 별도로 기록합니다. G1에서 조건을 확정하고 규모·사양 변경 시 목표·비용 영향을 합의합니다.
